# 「我的名單」手機版清晰度設計

## 目標

客戶經理在展場將公司加入「我的名單」後，回到 Hunter Hub 首頁能先看清楚公司名稱；進入完整名單後仍可用最多兩個短標籤快速判斷下一步行動。

## 首頁「我的名單」預覽

- 維持最近加入三家公司的單層預覽。
- 每列只顯示色點及公司名稱，不顯示規模或任何其他標籤。
- 公司名稱維持單行省略並取得整列剩餘寬度。
- 整張卡片既有點擊行為、數量徽章與「還有 N 家」提示不變。

## 完整「我的名單」列表

- 只在寬度不超過 600px 時改用短標籤；桌面版保留完整標籤。
- 公司名稱仍維持單行。
- 每列最多顯示兩個短標籤，依序選取：
  1. 特殊狀態：`婉拒`、`合作`、`其他`。
  2. B 級：顯示 `B`；A 級不顯示。
  3. 廣交會期別：`1期` 或 `1/3期`。
  4. 業務線索：`保税` 或 `进出口`。
  5. 套保：`套保`。
- 企業規模不在手機短標籤顯示。
- 企業詳情頁繼續保留全部完整標籤及資料。

## 實作方式

- `canton140.js` 新增可單元測試的「我的名單」短標籤選取函式，與廣交會組合既有規則分開，避免在廣交會組合重複顯示套保。
- `index.html` 將廣交會組合及我的名單列標記為手機短標籤列，依目前組合呼叫正確的選取函式。
- 既有完整標籤 HTML 保留，由 CSS 媒體查詢在手機切換為短版。

## 安全與資料邊界

- 不改 D1 結構、加入／移除名單 API 或既有名單資料。
- 不上傳原始 Excel／CSV；Cloudflare Pages 繼續只部署公開檔案白名單。

## 驗收

- 首頁預覽三列不存在規模或其他標籤。
- 390px 寬度的完整我的名單，每列最多兩個短標籤且不裁切、不橫向溢位。
- 非廣交會的套保公司可顯示 `套保`。
- 廣交會組合仍沿用既有規則，不顯示重複的套保。
- 桌面版、詳情頁及加入／移除名單功能不變。
