# 第140屆廣交會＋套保名單設計規格

日期：2026-10-21  
狀態：使用者已核准設計方向，待規格複核後進入實作

## 目標

在 Hunter Hub 首頁的「組合篩選」新增「第140屆廣交會＋套保名單」，讓客戶經理查看廣交會展商與套保名單的 A、B 級比對結果，並依城市及廣交會期別篩選現場開發對象。

本功能延續 Hunter Hub 作為行銷名單入口的定位，不取代客戶經理對企業身分、關係與商機的人工確認。

## 現況與版本基準

- GitHub `insa1470/sales-database` 的 `index.html` 仍顯示 1,741 家，是較早版本。
- 2026-10-21 線上 `https://sales.deepmystic.net/` 顯示 2,475 家，且首頁、組合篩選及資料結構均較 GitHub 版本新。
- 實作前必須先把線上 `index.html` 與 `data.json` 保存為可追蹤的基準，再把功能套到該基準。
- 不可直接以舊 GitHub 首頁或舊 `data.json` 覆蓋線上版本。

## 名單範圍

資料來源為已完成的第140屆廣交會與套保名單比對結果：

- A 級：294 家，完整名稱一致。
- B 級：6 家，核心名稱一致或高度近似，需要使用者理解其為候選匹配。
- 合計：300 家。
- 與線上 2,475 家以正規化公司名稱比對後，34 家已存在，約 266 家需要新增；實作時仍須再做一次完整去重檢查。

所有 300 家都保留 `match_grade`，B 級不得呈現成已確認的完整名稱一致。

## 資料模型

新增獨立靜態資料檔 `canton140.json`，每筆至少包含：

```json
{
  "id": 2475,
  "supplier_no": "1433418317",
  "name": "深圳市福瑞斯健康科技有限公司",
  "phase": ["第1期", "第3期"],
  "section": ["家用電器", "醫藥保健品及醫療器械"],
  "booth": ["1.2L05-06，1.2K43-44", "9.2E12-14，9.2D34-36"],
  "province": "廣東省",
  "city": "深圳市",
  "address": "公司所在地",
  "capital": "CNY 20,000,000",
  "match_grade": "A",
  "match_reason": "完整名稱一致",
  "official_url": "https://365.cantonfair.org.cn/zh-CN/shops?id=1433418317",
  "data_status": "廣交會展商資料，未經工商核驗"
}
```

資料規則：

- `phase`、`section`、`booth` 使用陣列，支援同一展商跨期或跨展區。
- `id` 是 Hunter Hub 的穩定整數識別碼；它與廣交會 `supplier_no` 分開保存。
- 城市統一為現有 Hunter Hub 的中文格式，例如 `深圳市`、`東莞市`。
- 15 家缺少城市或資本額的欄位保持空值，畫面顯示「待確認」，不得從公司名稱推測。
- 註冊資本保留廣交會顯示的原始幣別及數值，不換算、不推導，也不作為工商核驗結果。
- 廣交會公司資料來源標示為「廣交會展商資料，未經工商核驗」。

## 合併與識別碼

載入既有 `data.json` 後，再載入 `canton140.json`：

1. 產製 `canton140.json` 時以公司名稱正規化結果尋找既有企業，並把最終 `id` 固定寫入資料檔。
2. 已存在的企業保留原 `id` 與全部原欄位，瀏覽器合併時只新增 `canton140_info` 物件；其中保存期別、展區、展位、廣交會城市、廣交會資本額、匹配級別及官方頁面，不覆寫原工商欄位。
3. 新企業取得不與既有資料衝突的穩定整數 `id`，並保留於產製後的 `canton140.json`，不可在瀏覽器每次載入時重新編號；新企業同時從 `canton140_info` 映射必要的頂層名稱、城市與資本額，讓現有列表元件可以正常呈現。
4. 新企業的 `hedging` 設為 `true`，`canton140` 設為 `true`；既有 `source` 不覆寫。
5. 合併後相同正規化公司名稱只能有一筆企業記錄。

穩定 `id` 是必要條件，因為 D1 的 `user_lists.company_id` 使用該值保存「我的名單」。

## 首頁入口

在首頁「組合篩選」新增一張入口卡：

- Hunter Hub 介面文字維持現有簡體中文口徑。
- 標題：`第140届广交会 ＋ 套保名单`
- 說明：`A、B级共300家，可按城市与期别筛选`
- 圖示：延續現有組合卡樣式，使用展會語意圖示。
- 數量：依實際載入資料動態計算，不硬編碼。

點擊後進入一般名單頁，沿用現有搜尋、分頁、「我的名單」與企業詳情互動。

## 篩選行為

一般資料來源與既有組合篩選維持原本的城市、地區、企業規模篩選。

只有進入「第140屆廣交會＋套保名單」時，篩選面板增加「廣交會期別」：

- 第一期
- 第二期
- 第三期

規則：

- 城市與期別均可複選。
- 同一類別內採 OR；城市與期別兩類之間採 AND。
- 跨期展商只要包含使用者選中的任一期，即視為命中。
- 缺少城市者歸入「待確認」，使用者可單獨選取。
- 清除篩選必須同時清除城市及期別條件。
- 返回首頁或切換到其他組合時，不保留廣交會專用期別條件。

註冊資本本期只顯示，不提供金額篩選，避免未正規化幣別、單位或未經工商核驗的資料造成錯誤篩選。

## 列表與企業詳情

廣交會組合列表中的每筆企業顯示：

- 公司名稱
- 城市或「待確認」
- 第一期／第二期／第三期標籤
- A 級或 B 級標籤

企業詳情新增「第140屆廣交會」區塊：

- 匹配級別與匹配理由
- 期別
- 展區
- 展位
- 所在城市／地址
- 註冊資本；空值顯示「待確認」
- 資料聲明：`廣交會展商資料，未經工商核驗`
- 「查看廣交會官方頁面」外部連結

既有企業原本的工商、聯絡、地址與產業資訊保持不變。若既有工商資料與廣交會資料不同，兩者分區顯示，不互相覆寫。

## 錯誤與降級處理

- `canton140.json` 載入失敗時，Hunter Hub 其他 2,475 家資料、登入及「我的名單」仍可正常使用。
- 廣交會入口顯示資料載入失敗訊息，不顯示錯誤數量或空白頁。
- 單筆缺少城市、資本額、地址、展區或展位時，只顯示「待確認」，其餘欄位繼續呈現。
- 官方頁面連結使用新分頁開啟，並保留安全的外部連結屬性。
- 不修改 D1 schema，不刪除或重建既有使用者與名單資料。

## 測試與驗收

### 資料驗收

- 廣交會組合總數為 300。
- A 級為 294，B 級為 6。
- 合併後無正規化公司名稱重複。
- 所有企業 `id` 唯一且跨重新整理保持穩定。
- 期別資料支援跨期企業。
- 缺值保持空值，沒有從公司名稱推測城市或資本額。

### 互動驗收

- 首頁可看到新組合入口與正確動態數量。
- 點擊入口只顯示 300 家廣交會＋套保企業。
- 城市單選、複選與「待確認」有效。
- 第一期、第二期、第三期單選與複選有效。
- 城市＋期別交叉篩選結果正確。
- 搜尋、分頁、企業詳情及「我的名單」在新組合中正常運作。
- 切換其他組合時不出現廣交會期別篩選。

### 回歸驗收

- 原有組合篩選數量與行為不因新資料合併而被錯誤改寫。
- 原有登入、管理者頁面、D1「我的名單」及已認領名單功能正常。
- 行動裝置與桌面版均無水平溢出，篩選面板可以正常捲動。
- 先在本機或預覽環境完成驗收，再部署到 `sales.deepmystic.net`。

## 部署與回復
